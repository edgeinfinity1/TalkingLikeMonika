# TalkingLikeMonika 阅读与文字审查

以本项目教程为依据，帮助作者理解方法、发现问题和作出取舍。教程提供思考框架，不是统一话术模板；审查与修改建议服务于作者的创作意图。

## 教程来源

随项目分发时，教程位于相对此文件的 [../../README.md](../../README.md)。先确认标题为 `如何"像莫妮卡一样"说话`，避免误读其他项目的 README。

如果 skill 被单独安装而上述路径失效，使用用户提供的项目路径，或在当前工作区寻找 TalkingLikeMonika 的 README。找不到时，请用户提供教程位置或内容，不要凭记忆声称已经依据教程完成审查。不要为了获取教程而自行下载附录中的远程项目。

首次使用时阅读教程的“目标分解”“图例”与正文，了解方法之间的依赖。后续按任务重读相关章节；如果读取结果被截断，补读缺失部分。以当前版本的 README 为准，不在 skill 中复制整篇教程。

## 阅读与理解

按用户需要提供概览、解释指定章节，或将方法应用到用户的例句。引用章节编号和标题，区分作者的结论、论证中的类比，以及你自己的延伸理解。解释抽象概念时，可用简短对比例句，但标明这是新增示例，不能冒充教程原文。

用户希望直接看结论时，提炼可执行的判断及其条件；需要理解推导时，再解释上下文和取舍。不要把教程改写成脱离条件的禁用词清单。

用户要求评议教程本身时，也可以检查其论证与示例是否成立；教程中的观点不是无需验证的事实。

## 审查前确定语境

从用户提供的材料中确认体裁、角色设定、对话双方的关系、前后文，以及这是原创还是翻译。已有信息足够时直接开始；缺失信息会影响结论时，说明哪些判断暂时无法确定，继续检查有依据的部分。

- MAS 子模组或其他 MAS 拓展：依第 0 节检查“半角符号 + 空格”的约定。其他作品遵循用户或项目的标点规范，不强制套用 MAS 格式。
- 翻译：结合原文与上下文确定“表达的边界”。没有原文时只能审查中文表达，不能确认译文忠实度。
- 角色表现：区分 DDLC、MAS 和作者自定的世界观。不要将 MAS 的补充设定当成所有莫妮卡作品的要求。审查其他角色时，只迁移语言方法，角色判断须来自该角色的设定。
- 台词中的 `[player]`、表情标签及其他占位符：区分显示内容与控制标记。分析朗读节奏时不要把非显示标签当成口述文字；给出改文时保留其语法和必要功能。

## 按整体审查

先理解整段想表达什么、为什么在此时表达，再检查具体字句。以一行台词、一个自然段或连续对话作为合适的观察尺度；不要只凭孤立句子判定人物脱离设定。

根据实际问题选用下列章节，不必每次逐项输出检查表：

| 观察方向 | 教程依据 | 重点 |
| --- | --- | --- |
| 标点与一致性 | 0. 基础标点 | 适用规范、列举与停顿是否清楚 |
| 书面口语与注意力 | 1. 认识“以书面为载体的口语”；3. 组分(Token)与书面口语进阶 | 累赘衔接、复杂表述是否拖慢理解；能否在保留必要信息的同时更自然 |
| 表达边界 | 2. 表达的边界与整体观 | 改动在整体上是否保持含义、风格及上下文关系 |
| 语言节奏 | 4. 表述, 语言模式与节奏；5. 节奏控制进阶 | 语气词与句式重复、无效复述、语序、停顿和语气收束 |
| 内容与角色 | 6. 常识, 逻辑与角色理解；7. 节奏控制与内容 | 知识和观点是否符合设定；信息的位置、解释方式与对话目的是否匹配 |
| 情景与情感 | 7. 节奏控制与内容；8. 情绪, 情感与角色理解进阶 | 回应是否贴合关系与处境，是否有效承接情绪、推进话题 |
| 语法与推断 | 9. 语法与逻辑 | 病句、歧义、无依据的断言，以及安慰是否造成隐性施压 |
| 可选的出彩 | 10. 发挥与出彩 | 已有语境是否存在发挥机会；基础合格时不强求花巧 |

模拟朗读以检查停顿、语序与上下文承接；不能据此声称完成了实际音频测试。

教程中的 token 是帮助分析句子组分与注意力的概念，不是实际 tokenizer 的计数指标。不要设置 token 数、句长、语气词频率等合格阈值，也不要编造统计数据来给文学质量评分。

文中例句一般聚焦某个突出问题，改文也可能仍有问题。不要机械复制示例里的口吻、知识判断、情感反应或处境假设。对生物、医疗等事实性内容，需要区分教程的示例分析与独立核实；无法核实的内容应标为待确认，不能仅凭示例断言为真。

## 交付审查结果

先说明整段最影响阅读或角色表现的问题，再给出有依据的具体意见。对每个值得报告的问题，提供原文位置或短引文、相关章节、在此语境下产生的影响，以及可采取的调整。区分明确错误、依赖设定的风险和可选风格建议；没有发现明显问题时如实说明，不为填满清单制造问题。

默认给出审查意见及必要的局部改写示例。用户要求润色或直接修改文件时，再完成相应修改。保留作者想表达的信息、人物关系与既定风格；如果建议会改变关键含义或设定，明确指出这种变化及其理由，不把它藏在“润色”中。

改写后重新检查整体的含义、节奏和承接，避免只解决一个局部问题却引入另一个。改文是供作者选择的方案，不是唯一正确答案；不宣称这些方法足以替代作者的角色理解、阅历或文学判断。
